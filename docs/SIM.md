# EH3D-PHOENIX-PCB: circuit simulation

The crate `eh3d-phoenix-sim` and the command `phoenix sim` are the first step of phase F12 (requirement PPCB-022). They simulate linear circuits and circuits with diodes, bipolar and MOS transistors, voltage-controlled switches, operational-amplifier macromodels and comparators with a solver of our own, by modified nodal analysis, and link no engine (the decision is `docs/adr/0010-own-circuit-simulator.md`, provisional). The non-linear devices, the report of a DC solution, the DC sweep and the analysis lines of a netlist are described in `docs/SIM_NONLINEAR.md`.

**State: prototype.** The results are an own numerical approximation. The tests use values of the textbooks and properties (superposition, conservation of current, repeatable results), and a coherence check compares the simulation of a filter with the RF crate. Nothing has been compared with SPICE or with a measurement, and the device models are simple (see "The device models" below for what they leave out).

## The netlist

A SPICE-style text. The first line is the title (as in SPICE it is never an element). A line starting with `*` is a comment, `;` starts a comment in the rest of a line, and a line starting with `+` continues the one before. Node names are not case sensitive (they are kept in lower case); `0` and `gnd` are ground. Element names are not case sensitive either (`r1` and `R1` are the same element).

| Line | Element |
|---|---|
| `Rname n1 n2 value` | resistor (above zero) |
| `Cname n1 n2 value [ic=v]` | capacitor, with an optional initial voltage |
| `Lname n1 n2 value [ic=i]` | inductor (above zero), with an optional initial current |
| `Vname n+ n- [DC v] [AC mag [phase]] [SIN(...) \| PULSE(...) \| PWL(...)]` | voltage source (a bare number is the DC value) |
| `Iname n1 n2 ...` | current source; the current flows from `n1` to `n2` through the source |
| `Ename n+ n- nc+ nc- gain` | voltage-controlled voltage source |
| `Gname n1 n2 nc+ nc- gm` | voltage-controlled current source |
| `Fname n1 n2 Vsource gain` | current-controlled current source |
| `Hname n+ n- Vsource rm` | current-controlled voltage source |
| `Kname L1 L2 k` | coupling of two inductors, `0 < k < 1` |
| `Dname anode cathode model` | diode |
| `Qname c b e model` | bipolar transistor (NPN or PNP by the model) |
| `Mname d g s b model [W=..] [L=..]` | MOSFET of level 1 (N or P channel by the model); the bulk is read and not used |
| `Sname n1 n2 nc+ nc- model` | switch controlled by the voltage between `nc+` and `nc-` |
| `Uname in+ in- out model` | operational amplifier or comparator, by the model |
| `Xname n1 n2 ... subckt` | instance of a subcircuit |

* Values take the suffixes of SPICE, not case sensitive: `f p n u m k meg g t` and `mil`. Letters after the suffix are a unit that is ignored (`10kOhm`, `1uF`). As in SPICE, `M` is milli and `F` is femto.
* `SIN(vo va freq td theta phase)`, `PULSE(v1 v2 td tr tf pw per)` and `PWL(t1 v1 t2 v2 ...)`. The DC value of a source with a waveform and no DC value is where the waveform starts (`vo`, `v1`, the first point).
* `.param name=value ...` defines parameters; a value, a gain or an initial condition may be an expression between braces, `{2*r1+1k}`, with `+ - * / ^`, parentheses, `pi`, `sqrt abs exp ln log10 sin cos` and the parameters defined before.
* `.model name TYPE(PARAM=value ...)` with the types `D`, `LED`, `ZENER`, `NPN`, `PNP`, `NMOS`, `PMOS`, `SW`, `OPAMP` and `COMP` (the parameters are in "The device models"). A parameter that is not known is read and left out, and the line is noted in `Netlist::ignored`. A parameter that is not given takes the default of the settings (`config/sim.cfg`) or, for the ones the settings do not hold, the default of SPICE.
* `.subckt name ports ... / .ends` defines a subcircuit (without parameters, and not inside another one; a subcircuit may call another, and a `.model` may be written inside it). It is expanded when the circuit is compiled: its nodes and elements get the prefix of the instance (`x1.m`, `x1.R1`: the prefix is the name of the instance in lower case, the name of the element keeps its case). A model written inside a subcircuit belongs to it and hides a model of the netlist with the same name; each instance gets its own copy (named with the prefix of the instance). The nesting is bounded by `max_subckt_depth`, which also stops a subcircuit that calls itself.
* `.op`, `.dc source start stop step`, `.tran tstep tstop [uic]` and `.ac lin|dec|oct points start stop` are read into the netlist (`Netlist::analyses`) and written back by `to_spice`; `phoenix sim` runs the first of them when no analysis is named. `.include name` is allowed only for a file in the same folder as the file that names it. `.print`, `.options` and the other directives are read and left out.

Errors name a code and the line of the netlist: a line that is not valid (`PHOENIX-SIM-001`), a value (`-002`), an element that is not supported (`-003`), a name used twice (`-004`), a reference to a model, a subcircuit, a parameter, an inductor or a voltage source that is not there (`-005`), a bad subcircuit (`-006`), a limit of the settings (`-008`), a model of another kind than the element asks for (`-022`), an `.include` that is not allowed (`-023`), an analysis line that is not valid (`-024`). `to_spice` writes a netlist back in a fixed order (parameters and models sorted by name, then the subcircuits, then the elements), and what it writes reads back as the same netlist.

## The analyses

The unknowns are the voltages of the nodes (not ground) and the currents of the voltage sources, inductors, and voltage-controlled and current-controlled voltage sources, named `v(node)` and `i(element)`. The current of a voltage source is the one that flows through it from the positive to the negative node, as in SPICE, so a source that feeds a load has a negative current.

* **Operating point** (`--op`). Capacitors are open, inductors are short, sources take their DC value. A circuit with diodes is solved by Newton-Raphson, with the limiting of the junction voltages of SPICE; the change must stay below the tolerances twice in a row. When the plain iteration does not converge, **gmin stepping** is tried (a conductance from every node to ground starts at `gmin_start` and is divided by `gmin_factor` at each of `gmin_steps` steps, each solution the start of the next, and then it is taken away), and when that fails too, **source stepping** (the sources are raised from zero in `source_steps` steps). The result says which strategy was used: `direct`, `gmin-stepping` or `source-stepping`. A node with no DC path to ground is reported with its name (`PHOENIX-SIM-010`) before the matrix is built; a matrix that cannot be solved (two voltage sources in parallel, a loop of inductors) names the unknown that is left undetermined (`-009`); an iteration that does not converge is `-011`. The result also gives the largest residual of the equations at the point.
* **DC sweep** (`--dc SRC START STOP STEP`). The operating point while one independent source takes the values `START + k STEP`; each point starts from the one before. See `docs/SIM_NONLINEAR.md`.
* **AC** (`--ac KIND N F1 F2`). The circuit is linearised at the operating point (a diode, a transistor or an output stage becomes its conductances, and a junction its capacitance, depletion plus diffusion) and solved in complex numbers at each frequency. `lin` gives N points in all, `dec` N per decade, `oct` N per octave; the stop frequency is added when it is not on the grid. For each unknown the table has the magnitude, the dB, the phase in degrees and the group delay `-dφ/dω`, taken from the phase a fraction `delay_step_fraction` of the frequency below and above it.
* **Transient** (`--tran STEP STOP`). Backward Euler or the trapezoidal rule (`--method be|trap`; trapezoidal by default). The first step is always backward Euler, which does not need the current of the capacitors before it. With `--adaptive` the answer of one step is compared with the answer of two half steps (the local error); the step shrinks when the difference is above the tolerances (`reltol`, `vntol`, `abstol`) and grows, up to the step asked for, when it is below. The step also **stops at the corners** of the sources: the rise, the top, the fall and the start of every `PULSE` (in every period), every point of a `PWL` and the delay of a `SIN`; after a corner the analysis starts again with a small backward Euler step, which keeps the trapezoidal rule from ringing at a jump. More than `max_breakpoints` corners is `PHOENIX-SIM-008`. A step at its minimum with an error above the tolerance is kept and noted (`PHOENIX-SIM-019`). An ideal edge (a rise or fall time of zero) puts the jump on the step that ends at the corner, which then shrinks to its minimum and is noted (`PHOENIX-SIM-019`); give the edge a short rise time. The fixed step does not look for corners. The analysis starts from the operating point, or with `--uic` from the initial conditions (`ic=` of capacitors and inductors, zero when missing). The sources take the value of their waveform at the time of each step.

The equations are solved by Gaussian elimination with partial pivoting written for this crate. A pivot that is zero, not finite or smaller than `pivot_tolerance` times the largest value of its column means the matrix is singular. The size is bounded by `max_unknowns`, the number of points of an AC sweep by `max_ac_points`, the steps of a transient by `max_tran_steps` and the size of a result by `max_result_cells`.

* **Noise** (library only, `noise_analysis`): the noise at the voltage of a node. Each source is a current source with a flat density in parallel with its device: `4kT/R` for every resistor (the parasitic resistances of the devices too, not the internal resistor of the op-amp macromodel), `2q|I|` for the junction of a diode (between its terminals) and for the collector and the base currents of a transistor, and `4kT * 2/3 gm` (saturation) or `4kT * gds` (triode) for the channel of a MOSFET. The circuit is linearised at the operating point as in the AC analysis, a unit current is injected where each source is and the squared magnitude of the voltage at the output times the density is its contribution; the contributions are added as powers. The result gives each contribution and the total in V^2/Hz, the density in V/sqrt(Hz) and the root mean square over the sweep (trapezoidal rule over the frequencies). There is no flicker noise, no noise of the op-amp and no noise referred to the input. The temperature is `temperature_c`.

## The device models

All of them are simple and none has been compared with SPICE. The parameters not listed are read and left out.

* **Diode** `D(IS N RS CJO VJ M FC TT BV IBV NBV)`: `I = IS (exp(v / (N Vt)) - 1)`; `RS` is a resistor between the pin and the junction (an internal node `d1.a`); the depletion charge follows SPICE (`CJO`, `VJ`, `M`, with the linear extension above `FC * VJ`) and the diffusion charge is `TT * I`, so the capacitance is `Cj(v) + TT * g(v)`; with `BV` the reverse breakdown adds `-IBV exp(-(v + BV) / (NBV Vt))`, which is `-IBV` at `-BV` (a Zener diode in reverse). The junction voltage is limited by the iteration in both directions.
* **Bipolar transistor** `NPN` or `PNP` `(IS BF BR NF NR VAF RB RC RE CJE VJE MJE CJC VJC MJC FC TF TR)`: the transport current `(If - Ir)(1 - vbc / VAF)` with `If = IS (exp(vbe / (NF Vt)) - 1)` and `Ir = IS (exp(vbc / (NR Vt)) - 1)`, the base currents `If / BF` and `Ir / BR`; `RB`, `RC` and `RE` are resistors in front of the terminals (internal nodes `q1.b`, `q1.c`, `q1.e`); the two junctions have depletion capacitance and the diffusion charges `TF * If` and `TR * Ir`. A PNP transistor is the same equations with the voltages and currents turned. There is no reverse Early voltage, no high-injection roll-off and no leakage current; the substrate node is not accepted.
* **MOSFET** `NMOS` or `PMOS` `(VTO KP LAMBDA W L CGS CGD)`: level 1 (square law), `beta = KP * W / L` with `W` and `L` of the line or else of the model, cut-off, triode and saturation with `(1 + LAMBDA * vds)`, the drain and the source swapped when `vds` changes sign. `CGS` and `CGD` are constant capacitors. No body effect (the bulk is not used), no sub-threshold current, no junction diodes.
* **Operational amplifier** `OPAMP(GAIN GBW VPOS VNEG ROUT)`: a transconductance of the difference of the inputs into a node with a resistor (`opamp_pole_ohms`) and a capacitor that put the pole at `GBW / GAIN` hertz (no capacitor when `GBW = 0`), then an output stage with `mid + half * tanh((v - mid) / half)` through `ROUT` when `VPOS` and `VNEG` are given (`mid` and `half` are the middle and half the range) and the voltage itself when they are not. The inputs draw no current. The limit is smooth, so the output approaches a rail and does not touch it; there is no slew rate, no input offset and no bias current.
* **Comparator** `COMP(VHIGH VLOW GAIN ROUT)`: the output goes from `VLOW` to `VHIGH` as `mid + half * tanh(GAIN * vd / half)` with `vd` the difference of the inputs, through `ROUT`. It has no hysteresis and no delay.

Nodes that only a gate, an op-amp input or a comparator input touch have no DC path to ground and are reported (`PHOENIX-SIM-010`). A transistor joins its base to its emitter and its collector for that check, because the junctions conduct.

## The netlist of a schematic

The netlist of a schematic is made without a netlist written by hand by the generator of `docs/NETLIST.md`: a table of models gives each part its model, values such as `4k7` and `1u5` are read, the nets get names that do not change, the subcircuits come from files of one folder and a report with the codes `PHOENIX-NETLIST-001` to `012` lists what cannot be simulated (`phoenix netlist`, and `phoenix sim --schematic` which chains it to the solver). What follows is the earlier translation by the letter of the designator, which `phoenix sim schematic.json` still uses.

`netlist_from_schematic` (and `phoenix sim schematic.json ...`, for the `design/schematic.json` of a project) turns the pins of each part into nodes through the nets, and the value of the part into the value of the element. The nets whose names are in `schematic_ground` (`0`, `gnd`, `agnd`, `dgnd`, `pgnd`) become node 0; nets with the same name are one node; a name is cleaned to letters, digits and underscores in lower case.

The kind of an element comes from the reference designator, which must be one letter followed by digits (the letters `Q M U` are read in a netlist but are not yet made from a schematic, because the schematic has no model for them): `R C L` (two pins, the value is the number), `V I` (two pins, the first is the positive one; the value is what follows the nodes in a netlist: `5`, `DC 5`, `SIN(0 1 1k)`), `D` (two pins; the anode is the pin `A` when the pins are named `A` and `K`, otherwise the first; the value is the name of the model, and a model with the default parameters of the settings is made for it), `E G` (four pins; the value is the gain), `F H` (two pins; the value is the controlling source and the gain, `V1 2`) and `K` (no pins; the value is `L1 L2 k`). Pins are taken in the order of their numbers.

Nothing is dropped silently. The report lists the parts that were translated and, with a code and the reason, the parts that were not (a kind that is not simulated, a number of pins that does not fit, a value that is missing or that does not read), the pins that are on no net (`PHOENIX-SIM-020`) and a schematic without a ground net (`-015`). The report is printed to the error output by the command and can be read in the eight languages.

## The check against the RF filters

`compare_filter` turns a ladder filter of `eh3d-phoenix-rf` (Butterworth, Chebyshev or Bessel; low-pass, high-pass, band-pass or band-stop) into a netlist, simulates it in AC over `coherence_points` frequencies from a tenth of its lowest edge (a ninth for band filters, so that no frequency falls on the centre, where a resonant branch has zero impedance) to ten times its highest, and compares the magnitude (dB), the phase (degrees) and the group delay (as a fraction of a period) of the output with the response that the RF crate computes from ABCD matrices. The tolerances are in the settings (`coherence_db_tolerance`, `coherence_phase_tolerance_deg`, `coherence_delay_tolerance`); a difference above them is `PHOENIX-SIM-018` with the figures. `phoenix sim --check-filter butterworth 3 lowpass 1meg` runs it from the command line. The two methods share nothing, so a difference means that one of them is wrong; agreement shows that they are consistent, not that either is right about a real filter.

## Output

CSV and JSON tables, deterministic: the same circuit and the same request give the same bytes, with no date, host name or program version. Numbers are written in the shortest form that reads back as the same number (`1.5e-3`). The JSON says `"kind": "own numerical approximation (prototype, not compared with SPICE)"`. `--probe v(out),i(v1)` chooses the unknowns; `--out BASE` writes `BASE.csv` and `BASE.json`, each as a temporary file and a rename (the folder is made when it is missing, and the rename is tried again `write_retries` times when another program holds the file).

## The command

```
phoenix sim [--config FILE] [--lang xx] [--json] [--out BASE] [--probe LIST] [--model FILE] <input> [<analysis>]
phoenix sim [--config FILE] [--lang xx] --check-filter FAMILY ORDER BAND F1 [F2] [--ripple-db DB] [--z0 OHM]
```

* `<input>` is a netlist, or a `.json` file with the schematic of a project.
* `--schematic FILE` takes a schematic (EAGLE, KiCad or the design model) instead of `<input>`, makes its netlist in memory from a table of models (`--models FILE`, `config/sim_models.cfg` by default) after the electrical rule check (`--no-erc` skips it) and runs the analysis; an error of the report stops the run (`docs/NETLIST.md`).
* The analysis is `--op`, `--dc SRC START STOP STEP`, `--ac KIND N F1 F2`, `--tran STEP STOP [--uic] [--adaptive] [--method be|trap]` or `--netlist` (prints the netlist and stops); without one, the first `.op`, `.dc`, `.ac` or `.tran` line of the netlist is run.
* `--model FILE` reads a file of `.model` and `.subckt` lines before the netlist; the file is only read.
* Numbers take the suffixes of SPICE (`1k`, `10meg`, `4.7u`).
* Exit code 0 when done, 1 when `--check-filter` finds a difference above the tolerances, 2 when the arguments, the settings, the input or the circuit are unusable.

## Settings and codes

`config/sim.cfg` holds every limit, tolerance and default. A missing line keeps the default; an unknown key or a value out of range is refused with its line number (`PHOENIX-SIM-007`). The codes are `PHOENIX-SIM-001` to `PHOENIX-SIM-024` in `docs/ERROR_CODES.md`, with titles in the eight languages.

## Tests and limits

The tests use the values of the textbooks: the voltage divider, the RC circuit at one time constant (63.2 %, with backward Euler and with the trapezoidal rule), the RL current, the corner of the RC low-pass at `1/(2πRC)` (-3.01 dB, -45 degrees, half the time constant of group delay), a series RLC with its resonant frequency, unit gain at resonance, the half-power points and `Q = f0 / bandwidth`, the half-wave rectifier (a peak one diode drop below the source, compared with the fixed point of the Shockley equation), and a transformer made of two inductors coupled with `k` near 1 (turns ratio `sqrt(L2 / L1)` times `k`, turned by half a turn). For the devices: the common-emitter amplifier (the rest point against a fixed-point iteration written in the test, the gain `-gm * RC` with `gm = Ic / Vt`, a half turn of phase, the conservation of current at its nodes), a PNP circuit that is the mirror image of the NPN one, the Early effect (the ratio of two collector currents), the current mirror (`Iout / Iref = BF / (BF + 2)`), a model of a subcircuit that hides the global one, the CMOS inverter (outputs at the rails and a threshold at 3 V for a P channel four times as wide, found by bisection), the non-inverting amplifier with an op-amp (gain `1 + R2 / R1`), the open-loop op-amp at its rails and the comparator at its levels, the gain-bandwidth product of the op-amp, the rectifier with a filter capacitor (the peak and a ripple below `Vp / (f R C)`), the Zener regulator (the output against the fixed point of the breakdown equation and a line regulation of a few millivolts), the series resistance of the diode, the capacitance of a reverse-biased junction (`Cj0 / (1 + Vr / Vj)^M`, seen as a corner in AC), the diffusion capacitance (`TT * g`), the charge of a junction against its capacitance by differences, a transistor switch in a transient analysis, the adaptive step landing on every corner of a pulse, and the noise of a resistor (`4kT R`), of an RC pair (`sqrt(kT / C)`) and of a diode (`2q I / g^2`). The properties are superposition in linear circuits, the conservation of current at every node and two runs with the same bytes. There are tests of the reader (units, expressions, continuation lines, subcircuits, parameters, models, every error with its line, damaged text that must not panic), of the writer (a netlist with every kind of element survives writing and reading), of the settings, of the codes (a title in each language, documented) and of the command.

Not done: nothing was compared with SPICE or with a measurement; the models are simple (see above), there is no temperature sweep (the temperature is one setting), no flicker noise, no `.step` and no `.measure`; the solver is dense and the number of unknowns is limited; a circuit that SPICE solves with its extra convergence aids may not converge here (a high-gain op-amp circuit that clips in a feedback loop may not); the netlist of a schematic knows only the parts whose reference designator is one of the supported letters and has no transistors; and the noise analysis has no command yet.
