# EH3D-PHOENIX-PCB: IPC-2581 export

The crate `eh3d-phoenix-ipc2581` and the command `phoenix ipc2581` write a board as an IPC-2581 file, the XML format that carries the layers, the outline, the pads, the nets and the bill of materials of a board in one document.

**State: prototype, write only.** The file follows the structure of revision C of the standard as far as this repository could build it from the public description, and it has been read back only by the XML reader of this repository. It has not been checked against the schema of the standard and has never been opened in a viewer or by a maker. There is no reader of IPC-2581 here.

```
phoenix ipc2581 [--config FILE] [--out FILE [--overwrite]] [--json] [--lang CODE] <board>
```

The board is a `.json` board, an EAGLE `.brd` or a KiCad `.kicad_pcb`, as for the other commands. Without `--out` the command is a dry run: it prints what the file would hold and writes nothing. With `--out FILE` the file is written there. The exit code is 0 when it is done and 2 when the arguments, the input or the output are unusable.

## Writing the file

A file is never replaced by chance:

* a name that does not exist is created exclusively (the call fails when something is already there, a link included);
* a name that exists stops the command (`PHOENIX-IPC2581-004`) unless `--overwrite` is given;
* with `--overwrite` the new file is made next to the old one with the name `FILE.new`, created exclusively, and moved over the old one, so a failure leaves the old file as it was; a `FILE.new` that is already there stops the command;
* the input board, a link and a folder are never replaced.

## What the file holds

* **Content**: the step, the layers, the bill of materials and the dictionary of standard shapes (circle, rectangle, oblong and rectangle with rounded corners), in millimetres.
* **The layers**: the copper layers in the order of the stack (the first is the top, the last the bottom, the ones between are internal; without an order, in the order of the layer ids), and the silkscreen, solder mask and paste layers, declared with their function and side. Only the copper layers carry features.
* **The profile**: the outline and its cutouts, as polygons that return to their first corner.
* **The padstacks**: one for each distinct pad and via: its shape, its drill and plating and the copper layers it is on. A hole that is not plated has a padstack with the drill only.
* **The packages and the parts**: each footprint in use as a package with its pins and a box around its pads as the outline, and each placed part with its footprint, its layer, its rotation, its mirror (parts on the bottom) and its place.
* **The nets**: each net with the pins on it.
* **The copper of each layer**, grouped by net: the pads of the parts (with their pin), the vias, the tracks as polylines (an arc as a curve with its centre and direction) and the zones as contours with their cutouts.
* **A basic bill of materials**: the parts grouped by value and footprint, with the quantity, the number of pins and the references with their layer.

Lengths are written as millimetres with up to six decimals and no trailing zeros; angles as degrees. The date of the history record is the setting `origination`, not the clock, so the same board and settings always give the same bytes.

## What it leaves out

The command says what is not in the file (`PHOENIX-IPC2581-006`, information, always given): the items of the silkscreen, the arcs of the outline (the outline is its corners), the copper fill of the zones (a zone is its outline and cutouts, before the clearances), the holes that are not plated (they are in the padstacks only), the documentation layers and the stack-up (thicknesses and materials), and what the settings switch off. A pad on none of the copper layers of the board is reported (`PHOENIX-IPC2581-008`) and an outline with fewer than three corners gives a file without a profile (`PHOENIX-IPC2581-007`).

## Settings

`config/ipc2581.cfg` holds every value and is also the built-in default: `origination`, `include_bom`, `include_tracks`, `include_zones` and `max_items` (the most parts, connected pads, tracks, vias and zones a board may hold for the file to be made, `PHOENIX-IPC2581-005`). A line that is not `key = value`, an unknown key or a value out of range is refused with its line number (`PHOENIX-IPC2581-001`).

## Codes

`PHOENIX-IPC2581-001` to `PHOENIX-IPC2581-008`, with titles in the eight languages (`src/codes.rs`) and the table in `docs/ERROR_CODES.md`.

## Limits

* Not checked against the schema of the standard and never opened in a viewer: a program that is strict about the order or the attributes of the elements may refuse parts of the file.
* The bill of materials has no manufacturer numbers: the part is named by its value and footprint.
* A part on the bottom keeps the layers its pads name; the mirror is written on the part and on its pads.
* Nothing has been compared with a file written by another tool.
