# EH3D-PHOENIX-PCB: IPC-2581 export and reader

The crate `eh3d-phoenix-ipc2581` and the command `phoenix ipc2581` write a board as an IPC-2581 file, the XML format that carries the layers, the outline, the pads, the nets and the bill of materials of a board in one document, and read such a file (`--read`, see "Reading a file" below).

**State of the writer: prototype.** The file follows the structure of revision C of the standard as far as this repository could build it from the public description, and it has been read back only by the XML reader of this repository. It has not been checked against the schema of the standard and has never been opened in a viewer or by a maker.

**State of the reader: run on real files.** It reads revisions A, B and C and has been run on 77 sample files of several design tools (see "What the reader was run on"); its counts agree with an independent count of the same files. It is not a validator of the standard, and a file is not checked against the schema.

```
phoenix ipc2581 [--config FILE] [--out FILE] [--d356 FILE] [--overwrite] [--json] [--lang CODE] <board>
phoenix ipc2581 --read FILE [--config FILE] [--html FILE] [--stackup-out FILE] [--overwrite] [--json] [--lang CODE]
```

The board is a `.json` board, an EAGLE `.brd` or a KiCad `.kicad_pcb`, as for the other commands. Without `--out` the command is a dry run: it prints what the file would hold and writes nothing. With `--out FILE` the file is written there. The exit code is 0 when it is done and 2 when the arguments, the input or the output are unusable.

## Writing the file

A file is never replaced by chance:

* a name that does not exist is created exclusively (the call fails when something is already there, a link included);
* a name that exists stops the command (`PHOENIX-IPC2581-004`) unless `--overwrite` is given;
* with `--overwrite` the new file is made next to the old one with the name `FILE.new`, created exclusively, and moved over the old one, so a failure leaves the old file as it was; a `FILE.new` that is already there stops the command;
* the input board, a link and a folder are never replaced.

## What the file holds

* **Content**: the step, the layers, the bill of materials and the dictionary of standard shapes (circle, rectangle, oblong and rectangle with rounded corners), in millimetres.
* **The layers**: the copper layers in the order of the stack (the first is the top, the last the bottom, the ones between are internal; without an order, in the order of the layer ids), and the silkscreen, solder mask and paste layers, declared with their function and side. Only the copper layers carry features of the board; a documentation layer that a dimension is drawn on is declared with the function `DOCUMENT` and carries the lines of the dimensions (extension lines, dimension lines, arrow heads and the pieces of the arc of an angle, each a polyline with round ends and the width of the stroke of the dimension), unless `include_dimensions` is false. Their texts are written too as a `Features` with the place of the text (`Location`), its turn (`Xform` with a `rotation`, only for a text that is turned, such as the one of a vertical dimension) and a `UserSpecial` with a `Text` that holds the characters and the height (`textHeight`, the height of the dimension, or `dimension_text_height_nm` when that is above zero), unless `include_dimension_texts` is false; the shape of that element has not been checked against the schema of the standard.
* **The profile**: the outline and its cutouts, as polygons that return to their first corner.
* **The padstacks**: one for each distinct pad and via: its shape, its drill and plating and the copper layers it is on. A hole that is not plated has a padstack with the drill only.
* **The packages and the parts**: each footprint in use as a package with its pins and a box around its pads as the outline, and each placed part with its footprint, its layer, its rotation, its mirror (parts on the bottom) and its place.
* **The nets**: each net with the pins on it.
* **The copper of each layer**, grouped by net: the pads of the parts (with their pin), the vias, the tracks as polylines (an arc as a curve with its centre and direction) and the zones as contours with their cutouts.
* **A basic bill of materials**: the parts grouped by value and footprint, with the quantity, the number of pins and the references with their layer.

Lengths are written as millimetres with up to six decimals and no trailing zeros; angles as degrees. The date of the history record is the setting `origination`, not the clock, so the same board and settings always give the same bytes.

## The IPC-D-356A netlist

`--d356 FILE` also writes the netlist of the board as an IPC-D-356A test file, the text that bare-board testers read to learn which pads are joined: one line of 80 columns for each pad of a part, with the net, the reference designator, the pin, the hole (diameter, plated or not), the side it can be reached from, the place and the size of the pad and its turn, in micrometres (`P  UNITS CUST 1`), between a header of three lines and the end record `999`. The records are in the order of the net, the part and the pin (so the same board gives the same file), a pad on no net has the net of the setting `d356_unconnected_name` (`N/C`), a name is written in printable ASCII (a blank becomes `_`, any other character `?`) and cut to the width of its field (net 14, part 6, pin 4), a pad whose place is beyond 999.999 mm is left out, and a size or a hole beyond 9.999 mm is cut; each of these is told in a `note:` line of the output (and in the key `d356` of `--json`, with the number of records). The columns are in the header of `crates/eh3d-phoenix-ipc2581/src/d356.rs`: 317 for a pad with a hole and 327 for a surface pad in columns 1 to 3, the net in 4 to 17, the part in 19 to 24, the pin in 26 to 29, `D` and the hole in 31 to 36, `A` and the side (00 both, 01 top, 02 bottom) in 37 to 39, `X` and `Y` and the place in 40 to 55, the size in 56 to 65, `R` and the turn in 66 to 69 and ` S` and the solder mask (0 both, 1 top, 2 bottom) in 70 to 72. **The columns were written from the published description as it is remembered; they have not been compared with the standard, with another tool or with a tester,** so a tester may need them changed. The file is made by the same rules as the other (a name that exists stops the command unless `--overwrite` is given), `--out` and `--d356` may not name the same file, and with only `--d356` no IPC-2581 file is written. `d356_include_smd` (true) says whether the surface pads are written, and `max_items` limits the pads.

## What it leaves out

The command says what is not in the file (`PHOENIX-IPC2581-006`, information, always given): the items of the silkscreen, the arcs of the outline (the outline is its corners), the copper fill of the zones (a zone is its outline and cutouts, before the clearances), the holes that are not plated (they are in the padstacks only), the texts of the dimensions when `include_dimension_texts` is false, the dimensions that cannot be drawn, the documentation layers that no dimension is drawn on and the stack-up (thicknesses and materials), and what the settings switch off. A pad on none of the copper layers of the board is reported (`PHOENIX-IPC2581-008`) and an outline with fewer than three corners gives a file without a profile (`PHOENIX-IPC2581-007`).

## Reading a file

`phoenix ipc2581 --read FILE` reads an IPC-2581 file (XML, revisions A, B and C, or a ZIP archive that holds one, read in memory: the reader never writes an entry to a folder, refuses names that leave it, and limits the entries, the unpacked bytes and the growth of an entry with `zip_max_entries`, `zip_max_total_bytes` and `zip_max_ratio`; `PHOENIX-IPC2581-015` and `-016`; an archive inside an archive is read two levels deep and the entry is named in the report). `phoenix check --ipc2581 FILE` is the same reading mode under the command that checks files and prints a report in the language of `--lang`, or JSON with `--json`. Nothing is written unless `--html` or `--stackup-out` names a file; a file that exists is replaced only with `--overwrite`, and the file that is read is never replaced.

What the reader takes from the file, with every length converted to whole nanometres:

* **Layers**: the name, the function (signal, plane, solder mask, paste, legend, core, prepreg, drill, outline, documentation, or the other function as written), the side, the polarity and the span of a drill layer.
* **Specifications and stack-up**: the thickness and its tolerances, the sequence, the group and the material of every layer of the stack-up, and from the specification it refers to the material name, the dielectric constant, the loss tangent, the resin content and the conductivity of a conductor (from `MHO/CM` to siemens per metre). A stack-up that sits in the old layer description or in the cad data is read the same way; a layer that names a group is the group and not a layer of the board.
* **Each step**: the origin, the profile and its cutouts (corners and arcs with their centres), the padstack definitions, the holes of the drill layers (diameter, tolerances, plated, not plated or via, place), the slots, the packages (name, kind, height, number of pins), the placed parts (reference designator, package, part, layer, mounting, place, rotation, mirror), the nets with their pins, the physical nets, and for every layer the number of pads, lines, arcs, polylines and regions, with their geometry (nets, widths from the dictionary of line descriptions or from the line, polylines with arcs, regions with cutouts) unless the setting `read_keep_geometry` is false.
* **Bills of materials**: the lines with the part, the quantity, the number of pins, the category and the reference designators.
* **The old form** of the format, with step lists, layer descriptions, padstacks that hold their holes and `LogicalNetPin`, is read too.

What it does not take is named: an element the reader does not know is left out and reported with its name and how many times it appears (`PHOENIX-IPC2581-012`), a length, a number or a unit that cannot be read is left out and reported with the attribute and the count (`PHOENIX-IPC2581-013`), and a file with no unit in the header is read in millimetres and says so. The dictionaries of shapes and colours are counted and not kept; a group of features placed with an `Xform` (a mirror about the vertical axis, a scale, a turn in degrees and the offsets, then the `Location`) is read with its coordinates already placed, an arc that is mirrored runs the other way round, and the number of such groups is counted for every layer.

The file is not trusted. The size of the file, the depth of the elements, the number of elements and the number of items (holes, parts, nets, pads, tracks, regions, lines of the bill) are limits that come from the settings `read_max_bytes`, `read_max_depth`, `read_max_elements` and `read_max_items`; a file over one is refused with `PHOENIX-IPC2581-011` and the message names the limit. The XML is read as a stream with no recursion, a name from the file is made safe to print (control characters become `?`, a long name is cut to 80 characters), bytes that are not UTF-8 are read as Latin-1 and the report says so, and nothing in the file can make the reader panic.

### The stack-up

The stack-up is the part of the report that a fabricator needs: for every copper layer, core, prepreg and solder mask from the top to the bottom, the thickness in micrometres, the material as the file names it and, when the file gives them, the dielectric constant and the loss tangent. The sum of the thicknesses is compared with the thickness the file declares. A value the file does not give is shown as `-` and reported (`PHOENIX-IPC2581-014`); nothing is made up.

`--html FILE` writes the stack-up as the page of HTML of `phoenix stackup --html`, in the language of `--lang`. `--stackup-out FILE` writes the stack-up and its materials as the first two parts of a job file for `phoenix stackup`; the lines to compute are empty and are added by hand. The file gives a dielectric constant and a loss tangent without a frequency, so each material has one point at the frequency of the setting `read_reference_mhz` (1000 MHz, which is 1 GHz, unless changed), which is the place to start from and is to be corrected. A layer without a thickness is left out and said; a dielectric without a constant has no material (the job is refused until the constant is written); a loss tangent that is missing is written as 0 and said; two layers with the same material name and other constants are two materials (`NAME` and `NAME #2`).

### What the reader was run on

77 sample files of several design tools were read for the check, kept outside the repository (their licence is not known) and not used by any test. Aggregated facts only:

* **Revisions**: 3 of revision A, 15 of revision B, 53 of revision C, and 6 without a revision attribute, in the older form with step lists. Sizes from 5 KB to 235 MB; the largest is read in about 3 seconds when the geometry is only counted.
* **Units** in the headers: `INCH` and `MILLIMETER`. `MICRON` and `MIL` are handled and did not occur.
* **Elements**: 117 different element names. 9 of them are not in the schema of revision C and belong to the older form (`LogicalNetPin`, `PadStack`, `LayerHole`, `LayerPad`, `LayerDesc`, `StepList`, `StepListRef`, `LayerDescRef`, `TextAttribute`); 9 attributes are not declared anywhere in that schema (`level`, `toolRef`, `certification`, `stepListRef`, `numberIO`, `context`, `stackupGroupName`, `materialType`, `gap`). The reader takes all of them, and the only element it leaves out in the whole set is the vendor extension `NonstandardAttribute`, by name.
* **Layer functions** that occur: `ASSEMBLY`, `BOARDOUTLINE`, `BOARD_OUTLINE`, `COATINGCOND`, `COMPONENT`, `CONDUCTOR`, `DIELADHV`, `DIELBASE`, `DIELCORE`, `DIELCOVERLAY`, `DIELPREG`, `DOCUMENT`, `DRILL`, `GRAPHIC`, `MIXED`, `PASTEMASK`, `PLANE`, `SIGNAL`, `SILKSCREEN`, `SOLDERMASK`, `SOLDERPASTE`. **Sides**: `ALL`, `BOTH`, `BOTTOM`, `INNER`, `INTERNAL`, `NONE`, `TOP`. **Plating**: `PLATED`, `NONPLATED`, `VIA`.
* **Sizes of the boards**: 2 to 18 copper layers, stack-ups of 11 to 46 layers, full boards 1.10 to 1.94 mm thick, up to 9 621 holes, 2 254 parts, 4 110 nets, 162 655 pads and 275 558 polylines in one file; the tolerances and thicknesses are written with up to 6 decimals.
* **The check**: for 76 of the 77 files (all but the largest) the counts of layers, holes, slots, parts, packages, padstack definitions, nets, pins on nets, physical nets, pads, lines, arcs, polylines, regions and lines of the bill were compared with the count of a second, independent program that reads the same XML with another parser, and there were no differences. No file was refused and none made the reader fail. The schema of the standard was not used to validate the files.
* **Placement**: a group of features placed with a turn, a mirror or a scale occurs in the file read from 4 of 22 sample archives; the reader applies it.

## Settings

`config/ipc2581.cfg` holds every value and is also the built-in default: `origination`, `include_bom`, `include_tracks`, `include_zones`, `include_dimensions`, `include_dimension_texts`, `dimension_text_height_nm` and `d356_include_smd`, `d356_unconnected_name` and `max_items` (the most parts, connected pads, tracks, vias and zones a board may hold for the file to be made, `PHOENIX-IPC2581-005`), and for the reader `read_max_bytes`, `read_max_depth`, `read_max_elements`, `read_max_items`, `read_keep_geometry`, `read_max_attrs` (the most attributes on one element), `read_max_findings` (the most findings listed), `read_reference_mhz`, and for ZIP archives `zip_max_total_bytes`, `zip_max_entries` and `zip_max_ratio`. A line that is not `key = value`, an unknown key or a value out of range is refused with its line number (`PHOENIX-IPC2581-001`).

## Codes

`PHOENIX-IPC2581-001` to `PHOENIX-IPC2581-014`, with titles in the eight languages (`src/codes.rs`) and the table in `docs/ERROR_CODES.md`.

## Limits

* Not checked against the schema of the standard and never opened in a viewer: a program that is strict about the order or the attributes of the elements may refuse parts of the file.
* The bill of materials has no manufacturer numbers: the part is named by its value and footprint.
* A part on the bottom keeps the layers its pads name; the mirror is written on the part and on its pads.
* Nothing has been compared with a file written by another tool.
