# EH3D-PHOENIX-PCB: requirements

This register is the single source of the state of each capability. Status values: planned, prototype, implemented, validated. Five requirements (PPCB-001, PPCB-002, PPCB-003, PPCB-029 and PPCB-030) are `prototype` and the other 25 are `planned`: none is validated and nothing has been run on real design files. High test coverage is not proof of geometric or electrical correctness, so each requirement says how it will be checked and what result is expected.

| Requirement | Description | Status | How it will be checked | Expected result | Known limits |
|---|---|---|---|---|---|
| PPCB-001 | Design model with stable object identities and integer nanometre coordinates. | prototype | automatic: property tests over thousands of generated models | Identities survive save, migration and reopening; references never dangle. | Only the foundations exist: checked nanometre and micro-degree values with the 2^30 nm range, orientation predicates in 64-bit integers, arcs as end points plus a sweep, UUID v7 ids from an injectable generator, and canonical JSON. There are no design objects, no references, no project file and no operations yet, so identities across save and migration are untested. |
| PPCB-002 | Reversible operations with undo and redo across domains. | prototype | automatic | A failed operation leaves the model unchanged; undo restores the intended state. | Only the board model has operations (nets, components, pad nets, tracks, vias) with an exact inverse, all-or-nothing batches and a replayable undo/redo history; tried on generated boards only. Schematic and other domains have none. |
| PPCB-003 | Own project format with one folder per domain, migrations, opaque data and atomic saving. | prototype | automatic: round trips, interruption tests | A corrupt file gives a diagnostic, never a panic; an interrupted save leaves a valid project. | The manifest, domains, links, migrations, opaque preservation, `must_understand`, read-only opening and atomic saving exist and are tested on generated projects; no migration is registered yet, the container's atomic replacement is tested but not inside a synchronised folder, and no real design has been saved. |
| PPCB-004 | Read and write EAGLE XML files (versions 6 to 9) with an import quality report. | planned | oracle: golden files, round trips | Nothing is lost silently; the report lists kept, transformed and dropped data. | Still `planned`: only a read-only summary exists (`eh3d-phoenix-eagle`: a bounded XML parser and counts of libraries, boards and schematics with consistency checks); it does not build the design model and there is no writer of EAGLE files from the model. First measurement over copies of a private corpus of 2263 files (`.lbr`, `.brd`, `.sch`), checked by SHA-256 against their originals: 734 are read (324 per thousand: 527 boards, 199 schematics and 8 libraries, versions 6.0 to 9.6.2) and the XML tree of each comes back identical after being written and read again; 1057 are refused because they start like the binary files of the old versions (`PHOENIX-EAGLE-012`; no reader here handles them), 401 are not XML for a reason not yet classified and 71 are XML but not EAGLE documents; the 734 read files raise one warning and no error. The rate is of the summary reader, not of the design model, and nothing is compared with the reference tool yet. |
| PPCB-005 | Read EAGLE binary files (versions 4 and 5), read-only, learned clean-room. | planned | oracle: pairs of binary and XML files | Same content as the XML written by the reference tool. | Not started: no limits known yet. |
| PPCB-006 | Compare results with the reference tool through golden files. | planned | oracle with EH3D-VALIDATION-LAB | The rate of agreement per level does not drop; every failure is classified. | Not started: no limits known yet. |
| PPCB-007 | Extract connectivity of schematic and board. | planned | oracle plus negative cases | Identical to the reference on the corpus; deliberately introduced errors are always found. | Still `planned`: the schematic crate checks a schematic against a board (parts, designators, values, footprints, pins and nets as groups in both directions) on hand-made cases, and the board crate computes the islands of each net (which pads, tracks, vias and zones touch on a layer) with exact integer arithmetic; arcs are judged by their end points only, the connectivity of a drawn schematic (wires, junctions, buses) does not exist because the schematic holds nets as lists of pins, and nothing has been compared with the reference tool. |
| PPCB-008 | Design-rule checks in a fixed order: copper clearance, minimum width, drill and annular ring, board edge, mask, silkscreen over pads. | planned | automatic plus oracle | Each finding carries a stable code; the report separates confirmed from inconclusive. | Still `planned`: a first part is written in the board crate (minimum width, drill, via size, annular ring and the clearance of straight track pieces and vias, from a rule file in millimetres) with exact integer arithmetic and confirmed and inconclusive findings kept apart; board edge, mask, silkscreen, pads, zones and arcs are not checked, and it has only been tried on small hand-made boards. |
| PPCB-009 | Export Gerber X2 and Excellon deterministically. | planned | automatic: two independent viewers, byte comparison | Output matches the model; two exports at different times are identical. | Still `planned`: `eh3d-phoenix-export` writes one Gerber X2 file per layer (pads, tracks with lines and arcs, vias, board outline, zones as their outline) and one Excellon file through the writers of EH3D-CORE-LIBS, identical for the same board; the files are read back by the parsers of the same library only, not by two independent viewers; no copper pour, no clearance, no pad rotation other than right angles, no plating information, no slots. |
| PPCB-010 | Export and import assembly formats (pick-and-place board and job files, mounting data, BOM and placement CSV). | planned | automatic with real samples | A round trip keeps the placements within a stated tolerance. | Not started: no limits known yet. |
| PPCB-011 | Export an `.eh3dproj` package at version 1.0.0 by default. | planned | automatic: conformance vectors | A consumer of the package reads it; newer versions only when consumers declare them. | Still `planned`: `eh3d-phoenix-export` builds a 1.0.0 package with the layer files and the drill file through EH3D-COMMON, byte for byte the same for the same board; the identity and time stamp come from the caller; no consumer program has opened a package made by it yet. |
| PPCB-012 | Read KiCad schematics, boards and libraries. | planned | oracle: public corpus with reviewed licences | The rate of identical connectivity does not drop. | Not started: no limits known yet. |
| PPCB-013 | Write KiCad schematics, boards and libraries. | planned | oracle | KiCad opens them and its checks agree. | Not started: no limits known yet. |
| PPCB-014 | PCB viewer: zoom, layers, highlighted nets, measures, grid and rule list. | planned | automatic plus manual review | Frame time and latency are measured with small, medium and large boards. | Not started: no limits known yet. |
| PPCB-015 | PCB editor: select, move, rotate, copy, delete, place, properties. | planned | automatic: operations tests | Every edit is a reversible operation. | Not started: no limits known yet. |
| PPCB-016 | Routing: 45 degree tracks and arcs, vias, widths per class, live rule checks, ratsnest and copper zones; a remote auto-routing task. | planned | automatic plus oracle | A re-routed board opens in the reference tool without warnings and its rule check agrees. | Not started: no limits known yet. |
| PPCB-017 | Schematic editor with electrical rule checks, transfer to the board and annotation by stable identity. | planned | automatic | A simple project can be taken from start to finish inside the tool. | Not started: no limits known yet. |
| PPCB-018 | Command console and script files, each command a reversible operation. | planned | automatic | The author's own scripts run with the same result as in the reference tool. | Not started: no limits known yet. |
| PPCB-019 | Script interpreter for the existing scripting language, sandboxed, with a compatibility report per script. | planned | oracle plus negative tests of the sandbox | Each script is reported as equivalent, adapted or pending with the cause. | Not started: no limits known yet. |
| PPCB-020 | Run output jobs of the reference tool. | planned | oracle: golden files | Same Gerber files as the reference tool. | Not started: no limits known yet. |
| PPCB-021 | Library sanitizer: inventory, geometric hash, fuzzy matching with manual confirmation, replace-and-relink with backup. | planned | automatic plus oracle | Replace-and-relink changes neither layout nor rule results on what it processes. | Not started: no limits known yet. |
| PPCB-022 | Circuit simulation through an existing engine with reference cases. | planned | automatic: analytic solutions | Results agree with the analytic cases within a justified tolerance. | Not started: no limits known yet. |
| PPCB-023 | Power-supply design assistant with declared ranges of validity. | planned | automatic plus physical measurement | Two real supplies are built and measured, and the deviation is understood. | Not started: no limits known yet. |
| PPCB-024 | RF tools by levels (analytic calculators first). | planned | automatic plus measurement | Each level states its scope and limits. | Not started: no limits known yet. |
| PPCB-025 | Bounded assistance by artificial intelligence. | planned | automatic: policy tests | Its proposals are reviewable differences and it never creates or starts machine jobs. | Not started: no limits known yet. |
| PPCB-026 | Mechanical steps: 3D view, STEP/IDF/glTF export, fit check against an existing enclosure. | planned | automatic plus review | Exports re-read with the same dimensions. | Not started: no limits known yet. |
| PPCB-027 | Computing tasks on the EH3D server. | planned | automatic: equivalence tests between backends | Same task gives the same result in process, as an external process and on the server. | Not started: no limits known yet. |
| PPCB-028 | User-facing text in eight languages from one source with stable keys. | planned | automatic: key checks in CI | No missing or extra keys. | Not started: no limits known yet. |
| PPCB-029 | Stable diagnostic codes from a registry kept in this repository. | prototype | automatic: a test per code | A code is never reused or renumbered. | The model, project and board crates map every failure to a registered code and keep `docs/ERROR_CODES.md` in step by test; not every code is produced by a test of its own yet. |
| PPCB-030 | Redacted mode for runs over a private corpus. | prototype | automatic: leak test | Only codes, counts, levels and hashes leave the machine. | Only the inventory command has it: its report holds counts, kinds, declared versions and one fingerprint, with a leak test over file names, folder names and file contents. The other runs it is meant for do not exist yet; tried only on folders made by the tests. |

Rules: a claim of correctness names the corpus, the tolerance and the tool version it holds for. A phase is complete when the measured rate does not drop, every failure is classified and fixed or documented, and the measured figure is reported.
